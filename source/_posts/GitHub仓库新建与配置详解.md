# GitHub 仓库新建与配置详解

<!-- more --> 

## 新建仓库完整步骤

**步骤 1：进入新建页面**

登录 GitHub 后，点击右上角 **"+"** 号 → 选择 **"New repository"**

**步骤 2：填写仓库信息**

按下面的说明逐项填写，每一项的含义都在下面解释。

**步骤 3：创建并关联本地仓库**

创建完成后，把本地仓库关联到 GitHub：

```bash
# 在本地仓库目录下执行
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
```

## 新建仓库时各配置项含义 

### 1. Repository name（仓库名称）

**含义**：仓库的名字，会显示在 URL 里

**作用**：唯一标识你的仓库，建议用英文、小写、连字符分隔

**示例**：my-project、git-tutorial

**注意**：创建后可以改，但 URL 会变，旧链接会失效

### 2. Description（描述）

**含义**：对仓库的简短说明

**作用**：让别人一眼知道这个项目是干嘛的

**是否必填**：选填，可以以后再补

**建议**：写一句话说清楚项目用途

### 3. Public / Private（公开 / 私有）

| 选项                | 含义                                           | 适用场景                                   |
| ------------------- | ---------------------------------------------- | ------------------------------------------ |
| **Public**（公开）  | 所有人都能看到你的代码，任何人都可以克隆、Fork | 开源项目、分享学习                         |
| **Private**（私有） | 只有你和你邀请的人能看到                       | 公司项目、个人未完成的项目、不想公开的代码 |

> **注意**：免费账户也可以创建私有仓库，但私有仓库的协作人数有限制。

### 4. Initialize this repository with a README（用 README 初始化）

**含义**：勾选后，GitHub 会自动帮你创建一个 README.md 文件

**作用**：

- ​	如果勾选了，仓库创建后就是**非空**的，你可以直接在线编辑或克隆下来
- ​	如果不勾选，创建的是**空仓库**，需要你本地先有代码再推送上去

**建议**：

- ​	新项目从零开始 → **勾选**，方便直接开始
- ​	本地已有代码要推上去 → **不勾选**，避免冲突

### 5. Add .gitignore（添加 .gitignore 文件）

**含义**：选择一个模板，自动生成 .gitignore 文件

**作用**：告诉 Git 哪些文件**不需要**被版本控制（比如编译产物、临时文件、密钥文件）

**常见选项**：

- ​	**None**：不添加
- ​	**Python**：Python 项目（忽略 **pycache**、.pyc 等）
- ​	**Node**：Node.js 项目（忽略 node_modules）
- ​	**Java**：Java 项目（忽略 target、.class 文件）
- ​	**VisualStudio**：VS 项目文件
- ​	**建议**：根据你用的编程语言选一个，以后可以再改


### 6. Choose a license（选择开源许可证）

**含义**：选择一个开源协议，规定别人能拿你的代码做什么

**常见许可证说明**：

| 许可证                    | 含义               | 特点                                                     |
| ------------------------- | ------------------ | -------------------------------------------------------- |
| **None**                  | 不选，保留所有权利 | 别人只能看，不能随便用、改、发                           |
| **MIT**                   | 最宽松的协议       | 别人可以随便用、改、发，只要保留你的版权声明就行         |
| **Apache 2.0**            | 宽松 + 专利授权    | 和 MIT 类似，但额外有专利保护条款                        |
| **GPLv3**                 | 传染性协议         | 别人用了你的代码，他的项目也必须开源（必须用同样的协议） |
| **BSD 2-Clause**          | 类似 MIT           | 非常宽松，几乎没限制                                     |
| **Creative Commons Zero** | 完全公有领域       | 相当于放弃版权，任何人想干嘛干嘛                         |

> **建议**：
>
> ​	想让更多人用你的项目 → 选 **MIT**
>
> ​	希望别人改了也要开源 → 选 **GPLv3**
>
> ​	不确定 → 选 **None** 或 **MIT**

## 仓库主页各功能按钮详解

进入仓库主页后，顶部有一排标签按钮，每个的作用如下：

### 1. Code（代码）

**图标**：<>

**作用**：显示仓库的文件列表、README、提交记录等

**你能做什么**：

- ​	浏览所有文件
- ​	在线编辑文件
- ​	查看 README（项目说明）
- ​	下载代码（Code 按钮）
- ​	克隆仓库

### 2. Issues（问题 / 议题）

**图标**：带感叹号的圆圈

**作用**：用来**提 bug、提建议、讨论问题**

**常见用法**：

- ​	发现代码有 bug → 开一个 Issue
- ​	想加新功能 → 开 Issue 讨论
- ​	记录待办事项

**Issue 里面有什么**：

- ​	**Labels**（标签）：给 Issue 分类，比如 bug、enhancement、question
- ​	**Milestones**（里程碑）：把多个 Issue 归到一个版本里
- ​	**Assignees**（负责人）：指定谁来处理这个 Issue

### 3. Pull requests（合并请求）

**图标**：分叉的箭头

**作用**：**你改了代码，想合并到原仓库时，就提一个 Pull Request（PR）**

**流程**：

1. Fork 别人的仓库到你自己账户

1. 你在自己仓库改代码

1. 提 Pull Request 给原作者

1. 原作者看到后，讨论、审核、决定是否合并

**你能做什么**：

- ​	新建 PR
- ​	看 PR 的讨论
- ​	看代码修改了哪里（Files changed）
- ​	审核 PR（Review）

### 4. Actions（自动化）

**图标**：圆圈里的闪电

**作用**：GitHub 的 CI/CD 功能（持续集成/持续部署）

**能干嘛**：

- ​	自动运行测试
- ​	自动构建项目
- ​	自动部署
- ​	代码提交后自动做一些事情

**简单说**：就是自动化流水线，不用你手动跑测试、打包了

### 5. Projects（项目看板）

**图标**：看板图标

**作用**：类似 Trello 的看板工具，管理项目任务

**能干嘛**：

- ​	把 Issue 和 PR 拖到不同列（待办、进行中、已完成）
- ​	可视化项目进度
- ​	团队协作管理任务

**适合**：团队项目、需要跟踪进度的项目

### 6. Wiki（知识库）

**图标**：书本图标

**作用**：写项目文档的地方

**能干嘛**：

- ​	写详细的使用说明
- ​	写开发文档
- ​	写 FAQ
- ​	比 README 更详细，支持多页面

### 7. Security（安全）

**图标**：盾牌图标

**作用**：检查项目的安全漏洞

**能干嘛**：

- ​	**Dependabot alerts**：自动检测你的依赖包有没有安全漏洞
- ​	**Security policy**：告诉别人怎么给你报安全问题
- ​	**Code scanning**：自动扫描代码里的安全问题

**简单说**：帮你自动找安全隐患

### 8. Insights（数据洞察）

**图标**：图表图标

**作用**：查看项目的各种统计数据

**能看什么**：

- ​	**Contributors**：谁贡献了多少代码
- ​	**Traffic**：仓库被访问了多少次
- ​	**Commits**：提交频率
- ​	**Pulse**：项目活动概况
- ​	**Dependency graph**：依赖关系图

### 9. Settings（设置）

**图标**：齿轮图标

**作用**：仓库的所有设置都在这里

**注意**：只有仓库所有者才能看到这个按钮

**详细说明见下一节**

## Settings 设置页面详解

### 1. General（常规设置）

| 选项                | 含义                                                     |
| ------------------- | -------------------------------------------------------- |
| **Repository name** | 修改仓库名称                                             |
| **Description**     | 修改仓库描述                                             |
| **Website**         | 填项目官网地址                                           |
| **Topics**          | 添加主题标签（比如 python、web、tutorial），方便别人搜到 |
| **Danger Zone**     | 危险区域：删除仓库、改公开/私有、转让仓库所有权          |

### 2. Branches（分支设置）

| 选项                        | 含义                                                         |
| --------------------------- | ------------------------------------------------------------ |
| **Default branch**          | 设置默认分支（一般是 main 或 master）                        |
| **Branch protection rules** | 分支保护规则：比如要求 PR 审核通过才能合并、必须通过测试才能合并 |

### 3. Collaborators（协作者）

​	**作用**：邀请别人一起开发你的仓库

​	**权限级别**：

- ​		**Read**：只读
- ​		**Triage**：能管理 Issue 和 PR
- ​		**Write**：能推送代码
- ​		**Maintain**：能管理仓库设置
- ​		**Admin**：完全权限

### 4. Webhooks（网络钩子）

​	**作用**：代码有变化时，自动通知别的系统

​	**常见用途**：

- ​		推送代码后自动部署
- ​		自动通知团队群
- ​		触发其他自动化流程

### 5. GitHub Pages

​	**作用**：把你的仓库变成一个网站

​	**能干嘛**：

- ​		直接放静态网页
- ​		写博客
- ​		放项目文档


**网址格式**：https://用户名.github.io/仓库名/

## 仓库主页右上角常用按钮

### 1. Code 按钮

​	**作用**：获取代码

​	**里面有什么**：

- ​		**HTTPS**：用 HTTPS 克隆（最常用）
- ​		**SSH**：用 SSH 密钥克隆（免密码）
- ​		**GitHub CLI**：用命令行工具克隆
- ​		**Download ZIP**：直接下载压缩包

### 2. Raw 按钮

​	**作用**：查看文件的原始内容（不渲染 Markdown）

​	**用途**：复制原始文本、查看真正的文件内容

### 3. Edit 按钮（铅笔图标）

​	**作用**：在线编辑文件

​	**注意**：编辑后会直接创建一个新提交

### 4. Star（星星）

​	**作用**：收藏这个项目，表示你觉得它好

​	**区别**：和收藏夹类似，别人也能看到你 Star 了哪些项目

​	**用途**：标记好项目、表示支持

### 5. Fork（分叉）

​	**作用**：把别人的仓库复制一份到你自己账户下

​	**用途**：

- ​		想改别人的项目 → Fork 下来
- ​		改完提 PR 给原作者
- ​		自己玩一份

### 6. Watch（关注）

​	**作用**：关注这个仓库，有新动态会通知你

​	**通知内容**：新 Issue、新 PR、新提交等

## 其他实用功能

### 1. Gist（代码片段）

​	**入口**：右上角 "+" → New gist

​	**作用**：分享单独的代码片段

​	**适合**：记笔记、分享小代码、做演示

### 2. GitHub Pages

​	**作用**：免费托管静态网站

​	**怎么开**：仓库 Settings → Pages → 选择分支和目录 → 保存

​	**适合**：个人博客、项目文档、作品集

### 3. Releases（发布版本）

​	**作用**：标记版本、发布安装包

​	**入口**：仓库主页右侧 → Releases

​	**能干嘛**：

- 给版本打标签
- 上传安装包
- 写更新日志
